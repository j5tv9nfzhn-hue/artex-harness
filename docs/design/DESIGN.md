## 二、提炼出的四条原则

1. **纸面，而非终端。** 旧版（本项目 S5 之前）是黑底绿字 + 全等宽，属于「渗透控制台」刻板印象：
   它让人紧张，也让密度不可控。参照 Claude 的做法改为**暖中性纸面 + 近黑正文 + 单一赤陶强调**，
   等宽只留给数据（命令、ID、revision、token）。屏幕从"电影里的黑客界面"变成"一台精密仪器"。
2. **衬线管层级，无衬线管阅读。** 标题与关键数字用衬线（`--serif`），正文用系统无衬线，
   代码/标识用等宽。三级字体各司其职 → 同样的信息量，可读性更高、层级更清楚。
3. **可控性必须被"看见"。** Claude Code Desktop 把权限模式、模型、目录放在提示框**下方一行**，
   而不是塞进设置页。因此本控制台的 composer 常驻一行控件：**模式 / worker 数 / 令牌用量**，
   并把「中断」与「纠偏」做成两个并列按钮（语义不同，不能合并）。
4. **每个动作都要能被查证。** Codex 的做法是让每条结论附终端输出/测试日志。因此工具卡默认
   **展示真实输出**（可展开/收起），拦截单独成色（琥珀＝平台管控，不是"失败"），
   并在「证据」页回答"哪些结论真的绑了流量"。

## 三、设计系统（实际落地的 token）

| 类别 | 取值（亮色 / 暗色） | 理由 |
|---|---|---|
| 纸面 `--paper` | `#f6f4ee` / `#171614` | 暖中性，久看不刺眼；不是纯白也不是纯黑 |
| 面板 `--surface` | `#fffefb` / `#201f1c` | 与纸面仅一级差，靠 1px 边框分层，不用重阴影 |
| 正文 `--ink` | `#1b1a17` / `#efece3` | 近黑（不是纯黑），纸面上更柔 |
| 强调 `--accent` | `#bd5334` / `#e08263` | 赤陶色，**全局只有一个强调色**；只用于当前态、主按钮、活跃标记 |
| 状态 | `--ok` 绿 / `--warn` 琥珀 / `--danger` 砖红 | 三色语义固定：完成 / 平台拦截 / 失败 |
| 字体 | serif 标题 · sans 正文 · mono 数据 | 见原则 2 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 | 4 的倍数，横向留白优先（24px 内边距） |
| 圆角 | 5 / 9 / 14 | 卡片 9，composer 14（唯一"软"元素） |

**刻意未采用**：图表仪表盘（覆盖率饼图/折线图）——harness 的答案在事件流里，不在趋势图里；
逐动作审批弹窗——决策 5 明确不要全审批（[ADR-0003](../adr/0003-capability-boundary.md)）；
纯等宽排版——牺牲可读性换"技术感"是廉价的。

## 四、布局：三栏工作区

```
┌──────────┬───────────────────────────────┬──────────────┐
│ 会话列表  │ 任务头（目标 / 状态 / rev / 预算） │ 检查器        │
│ （按状态  │ 轨迹 · 计划 · 回放 · 评测        │ 上下文/证据/  │
│  分组）   │ ─────────────────────────────  │ 能力/策略     │
│          │ 轮次时间线                     │              │
│          │ ─────────────────────────────  │              │
│          │ composer（模式/worker/令牌）    │              │
└──────────┴───────────────────────────────┴──────────────┘
```

- **左栏 = 并行工作的盘点**（Codex/Claude 都是"多会话并行"，需要常驻列表）。
  每项显示状态点、#id、运行中 worker、目标进度、high 漏洞数——判断"先看哪个"只需扫一眼。
- **中栏 = 一次运行本身**。轮次是最小视觉单位（详见第五节）。
- **右栏 = 按需展开的真相**。默认「上下文」，因为"它现在在干什么 / 花多少"是最常问的。

## 五、HARNESS 核心如何落到界面（本轮补的是这一层）

旧版只有骨架：有页面，但没有把 harness 的**循环语义**表达出来。本轮补的映射：

| HARNESS 能力 | 界面承载 | 之前 |
|---|---|---|
| **Turn（轮次）** | 时间线上一张带 `rev` / 类型 / 摘要 / **步数 · 错误 · 令牌** 的块 | 只有扁平日志行 |
| **终态原因** | 轮次头右侧统计；`result` 条目带原文 | 埋在正文里 |
| **工具调用 ↔ 结果配对** | `tool_use_id` 配对成**一张卡**（名字 / 参数 / 状态 / 输出） | 两行互不相干 |
| **平台拦截 ≠ 目标失败** | 拦截用琥珀色 + 「平台拦截」章 + 「平台管控」前缀说明；失败用砖红 | 只有 `is_error` 红色 |
| **中断 vs 纠偏** | composer 两个并列按钮 + 一行说明；纠偏不打断当前轮 | 只有"暂停" |
| **自主度模式** | composer 常驻 `模式：自动 / 人工审批`，并映射到真实的 `llm_judge` 开关 | 无入口 |
| **干预目标** | composer 顶部显示"纠偏目标 #id + 摘要"，可在轨迹/计划里点选 | 需自己记住 id |
| **证据** | 检查器「证据」页：有/无流量证据逐条列出 | 只有独立页面 |
| **能力** | 检查器「能力」页：5 类供给面 + `exec` 事实标记 | 独立页面 |
| **策略** | 检查器「策略」页：审批模式开关 + 硬拦截说明 + 可观测项 | 无 |
| **回放 / 评测** | 主标签页，直接调 `/api/harness/replay`、`/consistency` | 有但样式陈旧 |

> 所有控件都调**已存在的确定性 API**（`/api/harness/*`、`/api/tasks/{id}/intents/{iid}/steer`、
> `/api/intercept/judge`），没有为了好看而虚构能力；改不动的就如实只读。

## 六、静态演示为什么不手写

[`../demo/build.py`](../demo/build.py) 把 `server/console/app.css` 与 `app.js` **原样内联**，
只用一个 mock 层替换 `fetch()` 与 `EventSource`。于是：

- 演示走的是**生产渲染路径**——演示里的 bug 就是产品的 bug，不会出现"演示好看、真机拉胯"；
- 改完 UI 跑一次 `python3 docs/demo/build.py` 即同步，**不存在手抄漂移**；
- 产物仍是单文件、零外部请求，可 `file://` 直接打开（裸机无 Node 也能看）。

## 七、可访问性与细节

- 对比度：正文 `#1b1a17` on `#f6f4ee` ≈ 14:1，次要文字 `#8b857a` ≈ 4.6:1（≥ AA 正文门槛的边缘值，
  故只用于辅助信息）。
- 颜色不是唯一信号：拦截卡片同时有**文字标签**「平台拦截」与左侧色条；状态点后始终跟文字。
- 键盘：`⌘/Ctrl + Enter` 发送纠偏；Tab 顺序遵循 DOM（列表 → 标签 → 内容 → composer）。
- 滚动：跟随到底部时才自动滚动，向上翻阅时不打扰（`pinnedBottom`）。
- 暗色为主题变量切换，无硬编码颜色；`localStorage` 记忆。
