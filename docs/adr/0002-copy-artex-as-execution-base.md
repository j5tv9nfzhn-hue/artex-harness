# ADR-0002 · 关键决策：复制 ARTEX 作为执行底座（而非完全独立设计与实现）

状态：**已接受**　日期：2026-11-14

## 背景

需要在本仓库搭建一个"渗透向 WEB HARNESS"，三层（前端 / 后端 / 数据库）都要重做决策。
摆在面前的只有两条路：

- **A：复制 ARTEX 源码作为执行底座，在其上做改造**；
- **B：完全独立设计新的主题与排版布局（并重写执行层）**。

同时有一条硬约束：**保证模型的道德与行为表现与原版一致**（业主口径见
[ADR-0001](0001-owner-decisions.md) 决策 2——同提示词 + 同策略，验收为拒绝话术与行为逻辑一致）。

## 决定

**执行层选 A（复制底座），表现层选 B（UI 主题与排版完全重做）。**

即：保留 `agent/` `db/` `server/` `traffic/` `guard/` `intercept/` `llmpool/` `llmrec/`
`evidence/` `third_party/norma` 并尽量少改；上游 `web/`（Next.js）作为过渡界面保留，
新控制台另起、新主题、新信息架构。

> 落地修正：新控制台没有另建 `web-console/`，而是替换了 `web/` 本身（React 19 + Vite，
> 产物 `server/console-app/`）；上游 Next.js 前端已删除。

## 理由

### 为什么执行层必须复制

1. **行为一致性的载体是代码，不是文档**。"同提示词 + 同策略"意味着必须复用：
   8 份提示词种子（`agent/promptcatalog.go`）、20 条内置拦截规则与其话术、`guard` 的
   `PreToolUse/PostToolUse` 语义、norma 的工具串行/压缩/终止语义。任何重写都会在这些
   逐字决定模型表现的地方产生漂移，而漂移**无法事后校准**。
2. **研究结论支持"复用骨架"**：GitHub Copilot 团队的总结是"模型是引擎，harness 是车"；
   `deepclaude` 这类项目证明**循环架构而非模型身份决定行为**——反过来说，改 harness
   就是在改行为，所以改得越少越安全。
3. **上游的引擎判断是对的**：Event-driven + Frontier 优先队列，配合 CAS 领取
   （`server/engine.go:800/916/1237`）恰好匹配渗透域"长时程 + 串行依赖 + 人在环"的形态
   （对照 [02 §3.1](../02-HARNESS-RESEARCH.md) 的五种执行模式）。重写没有收益。
4. **稀缺资产已在上游**：HTTP 全留痕（`traffic/`）、漏洞证据快照与版本锁（`evidence/`）、
   LLM 原文录制（`llmrec/`）、幂等迁移（`db/schema.sql` 49 表）。重写这些等于重做三年。
5. **许可证层面 B 并不更自由**：即使用户选 B，只要仍复制代码就必须 AGPL（决策 1 已选 A）。

### 为什么表现层必须重做

1. **上游的信息架构就是它可控性差的来源**（见 [01](../01-EVALUATION-ARTEX.md) 现象②③）：
   任务页与对话页是两套聊天；意图只能 pause/resume/cancel；`steer_work` 只是模型工具、
   界面上没有入口；审批是独立页面而不是就地卡口。**换主题不解决这些，必须换 IA。**
2. 换 IA 后要新增四个一等公民页面（Run / Plan / Replay / Eval），与上游的
   "仪表盘 + 任务列表 + 覆盖图"信息层级冲突，改造量大于重写量。
3. 新控制台与上游 `web/` 并行开发，可以**分阶段替换**而不冻结开发（实际：新控制台直接替换了 `web/`）。

## 后果

**正面**

- 阶段 0 相对上游只有 **1 处代码改动**（`selfupdate` 更新源，见 PROVENANCE §3.1），
  为"行为一致"提供了最强保障；
- module 路径保持 `github.com/Autumn-27/artex`，534 个文件的 import 未动，未来可三方合并上游；
- 控制面全部是新包（`harness/`），与上游行为路径零耦合。

**负面 / 代价**

- 继承上游的结构性缺陷（④ 的非原子图读、② 的会话栈重复），需要按
  [04-ROADMAP](../04-ROADMAP.md) S1/S4 逐项修；
- 两个前端并存期维护成本上升（缓解：S5 完成即退场）；
- 仓库中同时存在"上游代码"与"本项目代码"，必须靠 PROVENANCE 与 ADR 保持可审计。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| B（完全独立重写执行层） | 行为一致性无法保证（决策 2 直接失效）；工期与风险不可接受；许可证上不占优 |
| 纯 A（连 UI 一起复制） | 把现象②③的 IA 缺陷一并继承，"人方便干涉"的目标无法达成 |
| 复制但改提示词/策略以"更好" | 直接违反决策 2；任何提示词/策略改动等于重做行为基线 |
