# S2 · 干预原语 + Run/Plan 控制台 MVP —— 交付与验收

阶段目标：[04-ROADMAP](../04-ROADMAP.md) 最高价值阶段——把"干涉"从**求模型**变成**调 API**，
并让它在界面上是一等公民。对应上游缺口 ①（意图不可改、纠偏无接口）与 ③（人工干涉差）。

## 一、交付结果

### 1. 六个干预原语（确定性 API，不经模型）

全部在 `server/harness_intervene.go`，**直接调用引擎既有方法**（`SteerWork` / `KillWork` /
`ControlWork` / `Notify()`），因此与 agent 走同一套生命周期锁，pause/delete/settle 竞态行为不变。

| 原语 | 路由 | 作用 | 上游状态 |
|---|---|---|---|
| **steer** | `POST /api/tasks/{id}/intents/{iid}/steer` | 运行中纠偏，**不中断当前轮**（worker 下个工具调用前消费） | 仅作为 planner/mainagent 的模型工具，无 REST |
| **kill** | `POST /api/tasks/{id}/intents/{iid}/kill` | 停止单条 work，不影响其它 | 仅 planner 的 `kill_work` 工具 |
| **edit-intent** | `PATCH /api/tasks/{id}/intents/{iid}` | 改 summary / asset_ids / priority | **完全没有**（无任何 UPDATE 路径） |
| **order** | `POST /api/tasks/{id}/frontier/order` | 按给定顺序重排 frontier | 排序固定 `priority DESC, id ASC`，不可调 |
| **replan** | `POST /api/tasks/{id}/replan` | 立即触发一轮规划 | 只能靠图变更或 ≥10min 心跳 |
| **pause-all** | `POST /api/tasks/pause-all` | 全局急停 | 只有逐任务 / 100 条批量（需先列 id） |

配套 `GET /api/harness/interventions` 返回原语清单，控制台据此渲染，**不硬编码**能力表。

**每次干预都记为一个 Turn**（`openHumanTurn`）：分配 revision、写入 `lifecycle` 事件，
于是干预在 transcript / 回放 / 评测里都可见，而不是"日志里没有、事后没人知道谁改的"。

### 2. 意图编辑的存储层（`db/intent_edit.go`）

| 语义 | 实现 |
|---|---|
| **补丁而非替换** | `payload = (payload - legacy keys) || frag`，只覆盖 patch 里出现的键 → `parent_ids` 等血缘键不会被顺手清掉 |
| **优先级是列** | `priority = COALESCE($4, priority)`，`0` 是合法值而非"不修改"（指针字段表达"未提供"） |
| **版本递增** | `content_version + 1` —— cold-digest 靠它判断折叠体是否过期（`agent/coldgraph.go` §5.3） |
| **只读边界** | 单条 UPDATE 限定 `kind='intent' AND state<>'deleted'` 且 `exploration_id=本任务` → 继承意图与已删除意图天然改不动 |
| **溯源** | 写入 `edited_by: "human"` 标记 |

`OrderFrontier` 把"第 1、2、3…"翻译成**严格递减的 priority**（起始值取当前最大值 + n + 1），
因此不需要新列/新索引，**worker 的领取查询一行未改**。

### 3. Run / Plan 控制台 MVP（`server/console/`）

> **历史说明**：本节记录的是 S2 当时的零构建 vanilla 控制台。它后来被 `web/`（React + Vite，
> 产物 `server/console-app/`，入口 `/app/`）取代并删除（提交 `60dfcf2`）。保留本节是为了
> 说明当时的取舍，不代表当前实现。

**选型决策：零构建静态应用（HTML + CSS + ES2020），无条件 `go:embed` 进单二进制。**

| 理由 | 说明 |
|---|---|
| 裸机优先（决策 4） | 目标机不需要 Node/npm；`go build ./cmd/artex` 出来的二进制**自带 UI** |
| 同源即可用 | 与上游前端同一端口，SSE 天然可用，无跨域/无单独静态服务 |
| 没有构建 = 没有产物漂移 | 与上游 `web/`（需 `next build`）解耦，S5 前也能独立演进 |
| 不依赖 CDN | 全离线可用（靶场/内网常见） |

页面与能力（MVP）：

- **任务栏**：任务列表 + 状态 pill + 全局急停；
- **Run**：SSE 订阅 `/api/harness/stream`，**按 revision 分组成 Turn 卡片**，
  区分 planner（蓝）/ 人工（绿）；每条 `tool_use` / `tool_result` / `text` 一行，
  意图锚点 `#12` 可点击；
- **干预坞**：选中意图后就地 **纠偏 / 停止 / 编辑（摘要+优先级）**；
- **Plan**：frontier 表格（按服务端领取顺序排列）→ 行内改摘要、改优先级、**↑↓ 调序 → 保存顺序**；
- **顶栏**：立即重规划、暂停/恢复、rev 与连接状态。

认证：登录返回 `{token}`，控制台存 localStorage **并写 `artex_token` cookie**——
cookie 是给 `EventSource` 用的（它不能设请求头），fetch 同时带 `Authorization: Bearer`。
这与上游 `web/src/lib/cookie.client.ts` 的做法一致，服务端 `extractToken` 本来就两种都收。

### 验收中发现并修掉的两个真实缺陷

1. **控制台 404**：`/console*` 最初注册在内层 `mux` 上，而 `mux` 只被挂到 `/api/`
   → 必须注册在 **root** mux。已修复并在代码注释里写明原因。
2. **`/console/` 无限 301**：`http.FileServer` 会把任何以 `/index.html` 结尾的路径重定向到
   `./`，导致 `/console/` → `/console/` 自环。改为直接从 embed FS 读出 index.html 写入。
   （回归测试 B11 覆盖此点。）

## 三、本阶段刻意的取舍

| 取舍 | 原因 |
|---|---|
| 不做"计划预审门" | 决策 5：不新增全审批式门禁；写权限只增加人的杠杆 |
| 意图编辑**不影响正在跑的 work 的提示词** | 上游语义：一次 work 的 system prompt 在启动时固定；编辑对下一轮生效，文档已写明，不假装是即时生效 |
| 控制台不引入框架/构建链 | 裸机优先 + S5 会继续长成完整 UI，零构建让每一步都能直接验证 |
| `replan` 在任务暂停时拒绝 | 与上游"暂停中不规划"一致，避免出现"点了却没反应"的静默失败 |
