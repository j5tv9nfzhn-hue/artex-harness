# S4 · 会话栈收敛与一致性修复 —— 交付与验收

阶段目标（[04-ROADMAP](../04-ROADMAP.md)）：收敛重复的会话栈（修 ②）、把能力做成注册表（P1）、
把证据完整性变成可见报告（只报告不强制），并按上游复核清单修掉仍开放的缺陷。

## 一、交付结果

### 1. 会话栈收敛：一个模型/运行默认值来源

**问题**（[01](../01-EVALUATION-ARTEX.md) §3 ②）：三个对话运行器（`MainAgent` 任务页、
`ChatAgent` 对话页、`SideQuestionService` 旁路）各自复制同一批 ~30 行设置，于是
"改一处要改两处"，且两个入口**可能悄悄漂移**——这正是"同一句话在不同入口得到不同行为"的根因。

**做法**：抽出 `agent/runopts.go` 的 `ModelRunConfig` —— **只收敛「模型/运行时管线」**：

| 收敛进 ModelRunConfig | 刻意留在各运行器 |
|---|---|
| 记录代理（WebFetch 代理 + CA 信任） | system prompt 正文 |
| 联网搜索（含 chat 页的按请求开关） | 工具面（任务图工具 vs 纯助手） |
| compaction 窗口 | 工作目录语义（tasks/<id> vs sessions/<sid>） |
| 流式/非流式 | 收尾（settlement）策略 |
| 输出上限 MaxTokens | todo store 的归属 |
| Bash 子进程的代理环境 | |

并新增两个访问器 `(*MainAgent).modelRunConfig()` / `(*ChatAgent).modelRunConfig(webSearchOn)`，
使两个运行器**从同一份配置生成 Options**。

**为什么不去动 planner/worker**：它们的 Options 差异是刻意的（意图写入 system prompt、
共享跨唤醒 todolist、run 级预算），把它们塞进同一个配置会抹掉这些语义 —— 那会是行为漂移而不是收敛。

### 2. 能力注册表（P1）

`harness/capability`：把 5 类供给面统一成一种"能力"对象，`GET /api/harness/capabilities` 暴露。

| 供给面 | 来源 | exec 语义 |
|---|---|---|
| `builtin` | `tools` 表 `kind='builtin'` | 默认可执行；**只读内置（图/记录/流量读取）显式标 false** |
| `custom-command` / `custom-script` / `custom-http` | `tools` 表对应 kind | 可执行 |
| `cli-wrapper` | `tools` 表 `kind='shell'` | **不可执行**（它只是"环境里装了什么"的声明，真正执行的是 Bash 工具） |
| `mcp` | `mcp_servers` + 缓存工具数 | 可执行（在本进程外运行） |
| `skill` | `skills/` 目录扫描 | 不可执行（是说明与参考材料） |

`readOnlyBuiltin` 是一张**显式白名单**而不是命名启发式：猜错的方向只可能是把执行面标成无害，
而那正是注册表绝不能错的方向。

实测：`builtin 51 + mcp 2 + skill 3 = 56`。

### 3. 证据完整性报告（只报告，不强制）

`db/evidence_integrity.go` + `GET /api/harness/evidence-integrity?task=`：
列出每个漏洞「有没有绑定流量证据」，给出总数/有证据/无证据与逐条明细（含绑定数、快照数、
是否已有报告），并附一句**明确声明**：不判断证据是否足以支撑结论、不阻止提交或导出。

按决策 5，这里**没有任何门禁**：报告让操作者决定，平台不替人做决定。

## 三、本阶段刻意的边界

| 边界 | 原因 |
|---|---|
| 不合并 `main_sessions` / `conversations` 两张表 | 迁移涉及前端路由与历史数据兼容，风险高、收益低于已完成的**代码层**收敛；表合并列入后续（不改行为的前提下） |
| 不动 planner/worker 的 Options | 它们的差异是行为语义（意图入 system prompt、共享 todolist），收敛即漂移 |
| 能力注册表不做风险评分 | 评分需要策略判断，会滑向"平台替人决策"，与决策 5 冲突；只报事实（surface/exec/agents/enabled） |
| 证据完整性不拦截 | 决策 5；且 TCP 类/未开启采集等场景本就无法绑定 |
| 上游第 5 条只做一半 | 保留同名覆盖语义（API 兼容），只消除半截文件；改成 409 会破坏现有前端契约 |
