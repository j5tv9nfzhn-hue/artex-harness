## 与上游已有的关系（不重复造轮子）

- 上游已有内容寻址证据 blob（`evidence/store.go`）、流量绑定（`finding_traffic_bindings`）、复测（`finding_retests`，结论 reproduced/fixed/inconclusive）、`db/evidence_integrity.go`（明确写着“这是报告，不是门”）、基础报告（`report.Markdown` / `FindingsMarkdown`）、流量分页（`traffic.Page`）。阶段二没有重写这些，而是在它们上面加了三层上游没有的东西：哈希链（防篡改证据）、强制门（不通过不让确认）、重放执行与专业报告模板。
- 复测结论 `fixed` 时门会挡住“再标为已确认”（已修复的漏洞不应再确认）；复测 `inconclusive` 时门挡住并提示人工判定；这与 `FinishFindingRetest` 里“fixed 结论自动改状态”的上游行为不冲突——那是复测结束时的状态流转，这是人工确认时的门。

## 前端接入（2026-11-21 追加）

控制台此前没有任何发现页与流量页，唯一能展示发现/流量相关数据的地方是右侧「系统」侧栏（`web/src/System.jsx`），所以四个入口都接在那里，不另开路由：

| 入口 | 位置 | 行为 |
|---|---|---|
| 审计链 | 系统侧栏新增「审计链」签 | `GET /api/harness/audit-chain`，显示验证通过/失败徽章、条目数、头哈希，逐条列出种类/时间/摘要/哈希；验证失败时显示失败原因并提示先核查审计文件。 |
| 验证门 | 系统侧栏「取证」签，每条发现下 | 未确认的发现有「标记为已确认」按钮；后端 422 时在行内列出全部失败原因，并给出人工越过理由输入框 + 「人工越过确认」按钮（理由必填，写入审计链）。已确认的发现显示已确认状态。 |
| F12 流量 + 重放 | 系统侧栏新增「流量」签 | `GET /api/traffic` 分页表：方法/状态/URL/大小/时间，host、方法、状态分桶、文本四种过滤；点一行展开原始请求/响应；「重放」按钮调 `POST /api/traffic/replay`，显示已复现/未复现、原始与重放状态、脱敏 curl（可复制）。流量未启用时明说。 |
| 专业报告 | 系统侧栏新增「报告」签 | `GET /api/report/pentest` 的 Markdown 直接渲染，并提供「下载 Markdown」按钮（`pentest-<任务号>.md`）。每次打开生成一份新报告并写一条审计记录。 |
